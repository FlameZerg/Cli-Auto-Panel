# 任务描述
修复通用配置无法删除、无法保存的历史问题，支持完整删除模板，增加应用通用配置的红绿代码差异，并移除别名卡片的“通用配置：”前缀。追加要求：移除通用配置的 v1 / v2 / v… 版本显示，将通用配置的“x 份文件”改为“x 份绑定”。

# 项目概述
React / TypeScript 前端与 Tauri / Rust 后端。通用配置保存在面板 SQLite 状态库中，别名配置文件和 PowerShell profile 通过现有操作计划与恢复日志提交。

# 分析
删除按钮和后端同时禁止删除被引用的模板，历史失效绑定会阻断模板清理。模板保存与全部文件同步耦合，失效或外部修改的文件会阻断保存。数据库写入比较原始 JSON 与重新序列化结果，旧版缺省字段可能导致状态未变却被拒绝。名称长度按 UTF-8 字节计算，与前端名称长度限制不一致。原预览只有操作前后全文，没有逐行红绿差异。新建表单直接改写草稿，反复选择模板可能累积旧片段。

# 提议的解决方案
1. 数据库按当前模型解析后比较状态，继续校验版本。
2. 删除在一次数据库提交中移除模板和全部绑定，包括清单外失效绑定；保留别名源文件、已落盘配置内容及恢复备份。
3. 新增仅保存模板入口，不访问 profile 或引用文件；同步仍遇到外部改动即停止，按每份绑定的实际内容与版本处理后续同步。
4. 草稿预览复用实际保存的剥离和合并逻辑，原文保持不变。共用逐行 diff 组件展示红删、绿增、原新行号和末行换行状态，预览请求按输入与状态版本隔离。
5. 别名卡片仅展示模板名称，独立保存模板后未同步文件展示待同步状态。
6. 移除模板卡片、通用配置选择框及页脚的版本显示，统一模板引用统计为“x 份绑定”；内部版本字段保留用于同步与冲突检查，真实文件总数仍显示文件数量。
7. 仅进行静态审查，不运行测试、编译或应用。
